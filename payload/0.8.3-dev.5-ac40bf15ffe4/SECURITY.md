# 安全边界

本插件适用于一个受信任操作人独占的 DSH/Harness 进程及私有数据目录。当前宿主的所有已认证浏览器会话代表同一 operator；本插件不提供多人登录身份隔离。`NATURAL_WORK_PRINCIPAL` 是进程主体，不是登录用户名；管理员由该本地主体初始化，不由第一个 HTTP 请求认领。

**不要将一个进程的登录地址、浏览器会话或数据目录共享给多个需要权限隔离的人。** 团队应为每人分别部署 OS 账号、宿主进程、数据目录和数据库只读账号；多租户共享进程需要宿主提供经过验证的用户身份接口后另行实现。网关认证不能把当前单 operator 进程变成多用户系统。

宿主负责 Host、Origin、浏览器认证及 Cookie 边界；插件沿用 `requestRejection`，POST 还要求 `application/json`。Python 只监听临时回环端口，持有独立随机令牌；拒绝缺失、错误、重复和非 ASCII 认证头。不要将 Python 端口暴露到网络。

只允许授权表上的只读查询。递归 AST 校验拦截写入 CTE、SELECT INTO、锁、未授权函数、会话变量和系统表；数据库只读事务提供独立防线。执行前把外层查询限制为最多 501 行，展示最多 500 行，并明确截断。单行超大值、昂贵扫描及恶意数据库仍需数据库资源配额；数据库只读账号也应限制权限。

PostgreSQL/TBase/Kingbase 和 MySQL 新连接默认 `verify-full`。MySQL 使用系统 CA，PostgreSQL 家族使用驱动默认 CA 或明确提供的 CA 路径。已有 PostgreSQL 的显式弱模式保留并提示风险；未保存 `sslmode` 的旧 MySQL 连接保留原连接行为，并提示迁移至 `verify-full`。显式严格校验下，证书不合格会连接失败。`require` 仅加密，`verify-ca` 不核对主机名，`prefer` 可退回明文，`disable` 禁用加密。后两者不适用于需要传输保护的环境；MySQL 不提供 `prefer`。Oracle/DM 需按厂商钱包或 TLS 配置独立验收。

连接密码仍使用本机私有文件（目录 0700，文件 0600）；这不是 KMS/系统密钥环。轮换先持久化新凭据，再切换引用并回收旧凭据。启动和请求恢复会清理孤儿引用；若清理写盘失败，管理接口返回 `credential_cleanup_pending: true` 并在下一次访问重试。已接纳的查询只在内存保留当时的 URL，轮换会取消查询；过期连接快照明确报冲突。备份也可能含旧密码，应按本机备份政策保护。

全新安装的依赖及 SHA-256 锁定在 `requirements.txt`，安装仍强制哈希校验并只用 wheel；`requirements.in` 是生成输入。升级已有 0.7.4 环境时按 `requirements-compatible.txt` 检查直接依赖和实际 API 能力，不因无关的间接依赖版本差异强制换环境，不下载或修改依赖。兼容检查不代表旧环境通过当前锁文件的漏洞审计；部署方仍按其维护策略更新依赖。诊断日志位于私有数据目录 `runtime/diagnostics`，每份至多 256 KiB，保留最近一份历史，过滤令牌、密码类行和 URL 口令。业务日志及导出可能含敏感业务内容，外发前需复核。

发现问题请通过已有交付渠道反馈构建 ID、复现步骤和脱敏日志；不要发送密码、令牌或客户原始数据。安全修复和依赖版本见 `CHANGELOG.md`，测试范围见 `VERIFICATION.md`。
